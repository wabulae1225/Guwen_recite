# 数学引擎：程序是怎么编写的

> **这份文档记「现状」**——数学模块现在怎么组织的、关键零件干什么、怎么往里加东西。
> 改了直接改这份。想知道某个决定是哪一轮定的、为什么，去 [`../LOG.md`](../LOG.md) 查。

数学模块两个文件，都是纯前端、零依赖、不联网：

```
math/index.html    交互：出题流程、自评、计时、错题本
math/engine.js     题目生成器，挂 window.MATH
```

---

## 一、和语文引擎的根本区别

语文那台引擎的四条根基假设，数学这边**全反过来了**。这是两台机器、不是一个模式：

| 语文（默写引擎） | 数学（速算引擎） |
|---|---|
| 题目是 `data.js` 里的静态文本，有限条 | 题目**现场生成**，无限量，不重样 |
| 挖空 = 遮住已有文本的一部分 | 算出一个原本不存在的答案 |
| 自评两档：我记得 / 我不记得 | 自评**三档**：算对了 / 算错了 / 没算出来 |
| 按句子内容存 key，记标记、错题、弱项 | **只存错题**，不做弱项归纳 |

共用的只有外壳：配色、版式、localStorage 的用法、「只练错过的」这个思路。
代码没有共用——两边各自独立，改一边不会碰坏另一边。

## 二、`engine.js`：题目生成器

### 结构

```js
window.MATH = {
  cats: [
    { id:"number", name:"数字计算", subs:[ {id, name, gen}, ... ] },
    { id:"trig",   name:"三角计算", subs:[ ... ] },
    { id:"vector", name:"向量计算", subs:[] },   // subs 为空 = 待建
    ...
  ]
};
```

**`subs` 为空的大类就是还没建的**，页面自动把它标成「待建」并禁止点击。
十个大类全部登记在案，建好一个填一个。

### `gen()` 的约定

每个细类就是一个 `gen()` 函数，调一次出一道题，返回：

```js
{ q: "37 × 84 = ?",        // 题面，可含简单 HTML（<sup> 之类）
  a: "3108",               // 答案，可含简单 HTML
  note: "可选的一行提示" }  // 没有就不给，页面自动不显示
```

**页面只认这三个字段**，不关心题目怎么造出来的。所以：

> **加一个细类 = 在对应大类的 `subs` 里加一条，页面代码一行都不用动。**

### 「算」和「背」不分家

同一套结构同时装两类东西：

- **算**：`gen()` 现场随机数、现场算答案（两位数乘法、质因数分解、分母有理化）
- **背**：`gen()` 从一张公式表里随机抽一条（三倍角、和差化积、诱导公式）

背的那类用了个通用零件 `formulaGen(list)`，传一个 `[题面, 答案, 提示?]` 的数组
就成一个细类，写起来几乎没有成本。

### 二级结论放哪

**不单开大类，散进各自所属的大类。** 因为「二级结论」是个属性、不是学科分支，
单开会和别的大类大面积重叠。现在三角里的 `sin⁴α + cos⁴α = 1 − ½sin²2α`、
`tanA + tanB + tanC = tanA·tanB·tanC` 就是按这个办法放的。
将来想专练，给条目加个标记、页面上加个筛选即可，不用改结构。

### 小工具

`ri(a,b)` 随机整数、`pick(arr)` 随机挑一个、`gcd`、`frac(n,d)` 约分成 `"3/4"`、
`simpRoot(k)` 把 √k 化到最简、`rootStr` / `rootFrac` 把根式写成字符串。
都是文件顶上那一段，加细类时直接用。

## 三、`index.html`：交互

### 状态

| 变量 | 是什么 |
|---|---|
| `cat` | 当前大类 id |
| `chosen` | `{大类id: Set(细类id)}`，每个大类各记各的勾选 |
| `queue` / `pos` / `shown` | 题目队列、当前位置、是否已翻答案 |
| `fromWrong` | 这一轮是不是「只练错过的」 |
| `tallies` | 本轮的 对 / 错 / 不会 三个计数 |
| `qStart` / `roundStart` | 两层计时的起点 |
| `pendingBad` | 刚点了「算错了」、等着填错答的那道题 |

### 一道题的流程

```
buildQueue()  按大类 + 勾选的细类，调 gen() 造 N 道，打乱
     ↓
render()      画题面，开始给这题计时
     ↓
reveal()      空格键。停表、显示答案和提示、亮出三档按钮
     ↓
grade(how)    1/2/3 键
     ├ ok    → 直接下一题
     ├ bad   → 记进错题本，弹出「我算成了…」输入框（可填可不填）
     └ none  → 记进错题本（标 how:"none"），直接下一题
     ↓
renderDone()  结束页：题量、正确率、三档计数、总用时、平均每题
```

### 为什么不做输入判分

手机上打不出根式、复数、向量、π。**自评三档是使用者定的**，理由是
「反正是我自己判，我也肯定不会瞎判」。「算错了」时那个**可选**的错答输入框，
是为了复盘时能看见错在哪儿——可选，因为有时候那个错答同样打不出来。

### 两层计时

- **每题**：`render()` 到 `reveal()` 之间。卡住说明这题有问题。
- **全轮**：第一题到结束页，另给平均每题。这是总熟练度。

## 四、错题怎么存

```js
localStorage["math_wrong_v1"] = [
  { cat, sub, catName, subName,   // 出处，用来在错题本里显示
    q, a, note,                    // 题面和答案的「快照」
    my,                            // 我算成了几（可为空字符串）
    how,                           // "bad" 算错了 / "none" 没算出来
    n,                             // 错了几次
    t }                            // 最后一次的时间戳
]
```

**存的是题面和答案的快照，不是生成参数。** 所以「只练错过的」是把存下来的
题面原样端出来，不是照参数重新生成。这是使用者的决定：

> 「错题暂时就只存错题吧，存参数之类的后面再想，这个可能就比较复杂，
> 可以把它保留成一个方向吧，就是如何智能的精准定制我可能不会的题，
> 这是一个很好的方向，但是这个可能我们先搭框架吧。」

**去重按题面文本**（`w.q === it.q`），同一道题再错一次就累加 `n`。

**换设备**：「我的错题」里能下载 `math_user.js`，或者把那段文本贴到新设备上导入。
页面启动时如果 `window.MATH_USER.wrong` 存在且本地还是空的，会自动吃进来。

## 五、往里加东西的两种情形

**加一个细类**（最常见）：在 `engine.js` 里找到对应大类的数组，加一条

```js
{ id:"newthing", name:"细类名", gen:function(){
    const a = ri(2, 20);
    return { q: a + " 什么什么 = ?", a: String(答案), note: "可选" };
  }},
```

背公式的用 `formulaGen`：

```js
{ id:"xxx", name:"某某公式", gen: formulaGen([
    ["题面 = ?", "答案", "可选提示"],
    ["题面 = ?", "答案"]
  ])},
```

**建一个新大类**：把 `window.MATH.cats` 里那个空的 `subs: []` 填上就行。
大类本身已经登记好了，页面会自动把「待建」去掉、按钮变成可点。

**加完必跑一遍自检**：把每个 `gen()` 跑上千次，看有没有抛异常、
有没有吐出 `undefined` / `NaN` / 空字符串；数值类的还要**独立验算一遍答案**
（用另一条路算同一道题，对不上就报出来）。这两道是质量底线，
v0.25 建两个大类时跑的是 29000 道 + 33000 道独立验算。

## 六、样式约定

CSS 全内联，配色变量和语文页同一套（宣纸底、朱砂红）。题面和答案用等宽字体
（`--mono`），因为是算式，对齐比好看重要。手机 390px 宽下测过，无横向溢出。
